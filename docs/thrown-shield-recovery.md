# Thrown shield recovery

The original `EntityThrownShield` reflects off solid blocks at 75% of its impact velocity; ordinary shields do not home. After an impact a shield is recovered when it comes within a speed-dependent distance of its owner (clamped to one through five blocks). On a slow block impact an ordinary shield is recovered within five blocks or dropped as an item. The electromagnetic version attracts toward the owner after 50 ticks; a block impact below 0.75 speed advances its age to 50. The port now implements these rules, retaining original item data across impact and recovery. The last magnetic step is capped to avoid overshooting.

The electromagnetic attachment is craftable with iron blocks, vibranium alloy, dwarf star alloy and redstone in the original pattern. An anvil combines a normal shield on the left with one attachment on the right for 30 levels, preserving the shield's data and durability. The upgrade sets the original `Electromagnetic` NBT flag, adds its tooltip, and hides the wrist/grip straps as in the original. Both variants are available in creative.

Unlike the original, the port retains separate 200-tick outbound and return safety limits: a projectile that does not hit anything enters the return phase and eventually drops if not recovered. The return timer and effective flight age survive saving. If a non-player owner is assigned by another mod, the item is dropped instead of discarded. The alternate shield request packet also retains the item if entity spawning fails. Some collision edge cases and precise legacy double-plant metadata behavior remain outstanding.

Glass and glass panes now break in a three-by-three plane aligned with the impact face, as in the original. The modifier's `canDoGriefing` value is captured at launch and saved with the projectile. Both `powers.allowGriefing` and `powers.allowThrownShieldGriefing` must be enabled; each block also requires a player owner, edit permission, world-border and loaded-chunk checks, and a non-canceled Forge break event. Unlike the original, protected or unbreakable glass is left intact and the shield rebounds if the impact block remains solid. The current Forge glass tags may differ from the old material classification. The shield also cuts vines along its flight path without starting a return, respecting the same permissions and canceled Forge projectile-impact events. This uses a separate outline trace because vines have no projectile collision in 1.20. The six original double-plant types also react: a lower-half hit removes the plant, while an upper-half hit leaves short grass below, as for the common original upper-half metadata. Both halves must pass protection checks, and the replacement additionally goes through a Forge placement event. Rare legacy upper-half metadata variants and exact drops are not yet reproduced; short grass itself is not a destructible impact block.

Regression GameTests exercise wall reflection, ordinary slow-impact recovery or drops, delayed magnetic attraction and slow-impact/save behavior, long-flight recovery with item data, the saved return deadline and non-player owners. These are server-side tests. Magnetic acceleration is server-authoritative: a synchronized active flag tells tracking clients when the projectile is magnetically returning, instead of treating a client's local entity age as the server's. A dedicated-server test with two real clients spawns a magnetic shield, brings an observer into tracking range late, and checks that the observer resolves its owner, renders it and receives the active flag while the server recovers the original item data. That test uses a summoned probe, not a manual throw or a subjective visual assessment; other multiplayer trajectories still need validation.

## Throw input

The original item throws on a primary-attack swing while `SHIELD_THROW` is held; pressing the ability key by itself does not throw. The port now follows that two-input gesture for the default Captain America bindings. The client sends a request only on an attack press while the ability is held. The server rechecks the active suit, enabled modifier, held key, main-hand item and cooldown, and applies the cooldown only after a successful spawn. The original pack's `THROW` sound event is used instead of the trident cue; like other Fisk sounds, it requires the external sound pack.

## Projectile rendering

The original `RenderThrownShield` draws the shield mesh in flight orientation and spins it by 32 degrees per unit of velocity. The projectile now uses the existing shield geometry directly with interpolated yaw, pitch and spin instead of the generic camera-facing thrown-item renderer. Velocity-driven spin is tested server-side and the client smoke test uses a temporary diagnostic texture to verify rendered pixels. Held shield poses use the actual wearer, including remote players. Electromagnetic model differences remain incomplete.

## Blocking permission

As in the original, raising Captain America's shield requires an active hero granting `USE_SHIELD` and no shared shield cooldown. The gate runs on both client and server. When raised, the item uses the original 35-degree yaw and pitch coverage, 80 shared shield health, 100-tick cooldown, durability loss and seven-tick repeat-hit guard. The hit that depletes the shield passes through. Vanilla's wider blocking arc is disabled for this item only. Held shields wait 20 ticks before regenerating ten shield health per second; without an active or held shield, recovery starts immediately. Fall damage while looking down and flight-into-wall damage are also blockable as in the original. The port supports both hands; the original predates vanilla offhand items.

## Impact

The original uses an indirect projectile damage source attributed to the thrower and wears the shield on a successful hit. The port uses a tagged shield-specific projectile source with the original translated death-message key, applies one durability point (including Unbreaking and creative rules), and applies the shield's Fire Aspect on successful hits. The original's impact damage calculation includes the shield's enchantment bonus, suit weapon attributes, strength and weakness, a 1.5 multiplier and speed scaling capped at full damage; the shield also adds six melee attack damage when held in the main hand and wears on a successful melee hit. The shield is redirected toward the thrower after an entity impact, using the original velocity-scaled impulse. Knockback and special block interactions still differ from the original.
